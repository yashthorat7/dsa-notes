## What are we solving?

Given an array of strings, group the strings that are **anagrams** of each other together. Two strings are anagrams if they contain the same characters with the same frequencies — just rearranged. The challenge is: **what key can we use to identify strings that belong to the same group?**

**Example 1:**
```
Input:  strs = ["eat","tea","tan","ate","nat","bat"]
Output: [["bat"],["nat","tan"],["ate","eat","tea"]]
```

**Example 2:**
```
Input:  strs = [""]
Output: [[""]]
```

**Example 3:**
```
Input:  strs = ["a"]
Output: [["a"]]
```

**Constraints:**
- $1 \le$ strs.length $\le 10^4$
- $0 \le$ strs[i].length $\le 100$
- strs[i] consists of lowercase English letters

## Approach 1 — Sorted String as Key ✅

**Key insight:** Anagrams, when sorted, produce the **same string**. "eat" → "aet", "tea" → "aet", "ate" → "aet". So we can use the sorted version as a hash map key, and group all strings that share the same key.

```
strs = ["eat","tea","tan","ate","nat","bat"]

"eat" → sorted "aet" → map["aet"] = ["eat"]
"tea" → sorted "aet" → map["aet"] = ["eat","tea"]
"tan" → sorted "ant" → map["ant"] = ["tan"]
"ate" → sorted "aet" → map["aet"] = ["eat","tea","ate"]
"nat" → sorted "ant" → map["ant"] = ["tan","nat"]
"bat" → sorted "abt" → map["abt"] = ["bat"]

Result: [["eat","tea","ate"], ["tan","nat"], ["bat"]] ✓
```

Clean and intuitive. Sorting each string is $O(k \log k)$ where $k$ is string length.

```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        unordered_map<string, vector<string>> groups;
        for (const string& s : strs) {
            string key = s;
            sort(key.begin(), key.end());
            groups[key].push_back(s);
        }
        vector<vector<string>> result;
        for (auto& [key, group] : groups)
            result.push_back(group);
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \cdot k \log k)$ | $O(n \cdot k)$ |

> **This is the one for interviews.** Simple, clean, easy to explain.

## Approach 2 — Character Count as Key

**Alternative:** Instead of sorting, count character frequencies and use that as the key. E.g., "eat" → "1a0b0c0d1e..." — or more practically, a string like "1#0#0#0#1#..." for the 26 letters. Avoids the $O(k \log k)$ sort.

```
"eat" → count: a=1,e=1,t=1 → key "1#0#0#0#1#...#1#..."
"tea" → count: a=1,e=1,t=1 → same key → grouped together
```

$O(k)$ per string instead of $O(k \log k)$, but the key string can be long and hashing it has overhead. In practice, sorting approach is often equally fast.

```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        unordered_map<string, vector<string>> groups;
        for (const string& s : strs) {
            int count[26] = {};
            for (char c : s) count[c - 'a']++;
            string key;
            for (int i = 0; i < 26; i++)
                key += to_string(count[i]) + '#';
            groups[key].push_back(s);
        }
        vector<vector<string>> result;
        for (auto& [key, group] : groups)
            result.push_back(group);
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \cdot k)$ | $O(n \cdot k)$ |

> Theoretically faster per string, but more code. Both approaches are accepted.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Empty strings | `[""]` — all empty strings are anagrams | Sorted empty = empty, groups correctly |
| Single character | `["a"]` → `[["a"]]` | Works naturally |
| No anagrams | All strings unique | Each gets its own group |
| All same string | `["abc","abc","abc"]` | All land in same group |

---

## Pattern Takeaway

**Canonical form grouping:** Transform each element into a canonical form (sorted string, frequency count) and use it as a hash map key. This pattern appears whenever you need to group equivalent items — anagrams, isomorphic strings, or any equivalence-class partitioning.
