## What are we solving?

We're given an integer array `nums`, and we need to check whether any value appears **at least twice**. If every element is distinct, return `false`. This is basically asking — "does this array have duplicates?" Seems trivial, but the question is really about **what data structure lets us check membership fastest**.

**Example 1:**
```
Input:  nums = [1,2,3,1]
Output: true
Explanation: 1 appears at index 0 and index 3.
```

**Example 2:**
```
Input:  nums = [1,2,3,4]
Output: false
Explanation: All elements are distinct.
```

**Example 3:**
```
Input:  nums = [1,1,1,3,3,4,3,2,4,2]
Output: true
```

**Constraints:**
- $1 \le$ nums.length $\le 10^5$
- $-10^9 \le$ nums[i] $\le 10^9$

## Approach 1 — Brute Force (Check Every Pair)

**Simplest idea:** For each element, check if it appears again later in the array. Two nested loops.

```
nums = [1, 2, 3, 1]

i=0, j=1: 1 vs 2 → no
i=0, j=2: 1 vs 3 → no
i=0, j=3: 1 vs 1 → match! return true
```

Works, but $O(n^2)$ — for $10^5$ elements, that's $10^{10}$ comparisons. Way too slow.

```cpp
class Solution {
public:
    bool containsDuplicate(vector<int>& nums) {
        for (int i = 0; i < nums.size(); i++)
            for (int j = i + 1; j < nums.size(); j++)
                if (nums[i] == nums[j]) return true;
        return false;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n^2)$ | $O(1)$ |

> Correct but TLE. We need faster lookups.

## Approach 2 — Sorting

**Better idea:** If we sort the array, duplicates will be adjacent. One pass after sorting to check neighbors.

```
nums = [1, 2, 3, 1]
After sort: [1, 1, 2, 3]

i=0: nums[0]=1, nums[1]=1 → match! return true
```

Sorting costs $O(n \log n)$, then one linear pass. Better than brute force, but we can do even faster.

```cpp
class Solution {
public:
    bool containsDuplicate(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        for (int i = 1; i < nums.size(); i++)
            if (nums[i] == nums[i - 1]) return true;
        return false;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \log n)$ | $O(1)$ |

> Good, but modifies the input. Can we do $O(n)$?

## Approach 3 — Hash Set ✅

**Best idea:** Use a hash set. For each element, check if it's already in the set. If yes → duplicate. If no → insert it. Hash set gives $O(1)$ lookup.

```
nums = [1, 2, 3, 1]
set = {}

num=1: not in set → insert → set = {1}
num=2: not in set → insert → set = {1, 2}
num=3: not in set → insert → set = {1, 2, 3}
num=1: already in set → return true ✓
```

Single pass, $O(1)$ lookups. This is optimal.

```cpp
class Solution {
public:
    bool containsDuplicate(vector<int>& nums) {
        unordered_set<int> seen;
        for (int num : nums) {
            if (seen.count(num)) return true;
            seen.insert(num);
        }
        return false;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(n)$ |

> **This is the one.** Linear time, clean and simple.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Single element | No pair possible → always `false` | Loop doesn't find a match |
| Two identical elements | Smallest duplicate case | Caught on first check |
| All same elements | Every pair is a duplicate | Caught immediately |
| Large array, all distinct | Set grows to size `n` | Returns `false` after full scan |

## Pattern Takeaway

This is the classic **"have I seen this before?"** pattern. Whenever you need fast membership checks — reach for a **hash set**. You'll see this same idea in Two Sum (hash map variant), finding intersections, and cycle detection.
