https://leetcode.com/problems/top-k-frequent-elements

## What are we solving?

Given an integer array `nums` and an integer `k`, return the `k` most frequent elements. The answer is guaranteed to be unique. This is really asking: **how do you efficiently find the top-k items by frequency?**

**Example 1:**
```
Input:  nums = [1,1,1,2,2,3], k = 2
Output: [1,2]
```

**Example 2:**
```
Input:  nums = [1], k = 1
Output: [1]
```

**Constraints:**
- $1 \le$ nums.length $\le 10^5$
- $-10^4 \le$ nums[i] $\le 10^4$
- $k$ is in range $[1,$ number of unique elements$]$
- Answer is guaranteed to be unique

## Approach 1 — Sort by Frequency

**First idea:** Count frequencies with a hash map, then sort by frequency and take the top `k`.

```
nums = [1,1,1,2,2,3], k = 2
freq: {1:3, 2:2, 3:1}
Sort by freq desc: [(1,3), (2,2), (3,1)]
Take top 2: [1, 2] ✓
```

Works, but sorting is $O(n \log n)$. The problem says we should do better.

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        unordered_map<int, int> freq;
        for (int n : nums) freq[n]++;
        
        vector<pair<int,int>> v;
        for (auto& [num, cnt] : freq) v.push_back({cnt, num});
        sort(v.rbegin(), v.rend());
        
        vector<int> result;
        for (int i = 0; i < k; i++) result.push_back(v[i].second);
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \log n)$ | $O(n)$ |

> Correct but we can avoid full sorting.

## Approach 2 — Min-Heap of Size K

**Better:** Use a min-heap of size `k`. As we iterate through frequencies, maintain only the top `k` elements. If heap size exceeds `k`, pop the smallest.

```
freq: {1:3, 2:2, 3:1}, k = 2
heap (min by freq):

Push (1,3): heap = [(1,3)]
Push (2,2): heap = [(2,2),(1,3)]
Push (3,1): heap size > k, pop min (3,1) → heap = [(2,2),(1,3)]

Result: [2, 1] ✓
```

$O(n \log k)$ — only maintaining a heap of size $k$, much better when $k \ll n$.

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        unordered_map<int, int> freq;
        for (int n : nums) freq[n]++;
        
        // min-heap by frequency
        priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
        for (auto& [num, cnt] : freq) {
            pq.push({cnt, num});
            if (pq.size() > k) pq.pop();
        }
        
        vector<int> result;
        while (!pq.empty()) {
            result.push_back(pq.top().second);
            pq.pop();
        }
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \log k)$ | $O(n)$ |

> Great for large $n$, small $k$. But can we go full $O(n)$?

## Approach 3 — Bucket Sort ✅

**Optimal idea:** The maximum possible frequency is `n` (all elements are the same). Create an array of buckets where `bucket[i]` holds all elements with frequency `i`. Then walk backwards from the highest bucket, collecting elements until we have `k`.

```
nums = [1,1,1,2,2,3], k = 2
freq: {1:3, 2:2, 3:1}

Buckets (index = frequency):
bucket[1] = [3]
bucket[2] = [2]
bucket[3] = [1]

Walk from right: bucket[3] → pick 1, bucket[2] → pick 2
Result: [1, 2] ✓
```

No sorting, no heap — just bucket indexing. $O(n)$ time.

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        unordered_map<int, int> freq;
        for (int n : nums) freq[n]++;
        
        int n = nums.size();
        vector<vector<int>> buckets(n + 1);
        for (auto& [num, cnt] : freq)
            buckets[cnt].push_back(num);
        
        vector<int> result;
        for (int i = n; i >= 0 && result.size() < k; i--)
            for (int num : buckets[i]) {
                result.push_back(num);
                if (result.size() == k) break;
            }
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(n)$ |

> **This is the one.** True $O(n)$ with no log factor.

---

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| `k = n` (all unique) | Return all elements | All buckets have 1 element |
| `k = 1` | Just the most frequent | Highest non-empty bucket |
| All same element | `[1,1,1], k=1` | Single bucket at index `n`, returns `[1]` |
| Negative numbers | Frequency counting works the same | Hash map handles negatives |

---

## Pattern Takeaway

**Bucket sort** is a powerful technique when the range of values is bounded. Whenever frequencies are bounded by $n$, you can replace $O(n \log n)$ sorting with $O(n)$ bucket indexing. Also keep the **min-heap of size k** pattern in your toolkit — it's the go-to for any "top-k" problem.
