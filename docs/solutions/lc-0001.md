## What are we solving?

Given an array of integers `nums` and an integer `target`, return the **indices** of the two numbers that add up to `target`. Each input has **exactly one solution**, and you can't use the same element twice. The classic first LeetCode problem — and it's really asking: **how fast can you find a complement?**

**Example 1:**
```
Input:  nums = [2,7,11,15], target = 9
Output: [0,1]
Explanation: nums[0] + nums[1] = 2 + 7 = 9
```

**Example 2:**
```
Input:  nums = [3,2,4], target = 6
Output: [1,2]
```

**Example 3:**
```
Input:  nums = [3,3], target = 6
Output: [0,1]
```

**Constraints:**
- $2 \le$ nums.length $\le 10^4$
- $-10^9 \le$ nums[i] $\le 10^9$
- $-10^9 \le$ target $\le 10^9$
- Exactly one valid answer exists

## Approach 1 — Brute Force (Check Every Pair)

**First instinct:** Try every pair of indices `(i, j)` and check if they sum to target.

```
nums = [2, 7, 11, 15], target = 9

i=0, j=1: 2 + 7 = 9 → match! return [0, 1] ✓
```

Got lucky here — found it on the first pair. But worst case, we check all $O(n^2)$ pairs.

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        for (int i = 0; i < nums.size(); i++)
            for (int j = i + 1; j < nums.size(); j++)
                if (nums[i] + nums[j] == target)
                    return {i, j};
        return {};
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n^2)$ | $O(1)$ |

> Works but slow. For each element, we're scanning the rest of the array. Can we look up complements instantly?

## Approach 2 — Hash Map (One Pass) ✅

**Key insight:** For each number `x`, we need `target - x` to exist somewhere else in the array. A hash map lets us check this in $O(1)$. As we iterate, we store each number's index — so by the time we find a match, its complement is already in the map.

```
nums = [2, 7, 11, 15], target = 9
map = {}

i=0, num=2:  need 9-2=7, not in map → store {2: 0}
i=1, num=7:  need 9-7=2, found in map at index 0 → return [0, 1] ✓
```

One pass, one lookup per element. Can't do better than this.

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> seen;  // value → index
        for (int i = 0; i < nums.size(); i++) {
            int complement = target - nums[i];
            if (seen.count(complement))
                return {seen[complement], i};
            seen[nums[i]] = i;
        }
        return {};
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(n)$ |

> **This is the one.** Single pass, $O(1)$ lookups, clean logic.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Two elements | Smallest possible input | Always returns `[0, 1]` |
| Duplicate values | `[3, 3], target=6` | Map stores first 3, finds second — works |
| Negative numbers | `[-1, -2, -3], target=-4` | Complement logic handles negatives naturally |
| Zero in array | `[0, 4, 3, 0], target=0` | Complement of 0 is 0 — found at different index |

---

## Pattern Takeaway

The **"complement lookup"** pattern is foundational. Instead of searching for a pair, search for what's *missing*. Hash map turns a nested loop into a single pass. You'll use this same idea in 3Sum (with two pointers after fixing one element), 4Sum, and many subarray sum problems.
