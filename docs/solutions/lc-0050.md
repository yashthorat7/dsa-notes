## What are we solving?

We're given a floating-point number `x` and an integer `n`, and we need to compute $x^n$ — basically, multiply `x` by itself `n` times. Simple enough on paper, but there's a catch: `n` can be **negative** (meaning we need to compute the reciprocal, like $2^{-3} = 1/8$) and it can go as large as $\pm 2^{31}$, which is roughly 2 billion. So brute-forcing it with a loop? That'll TLE instantly. The real question is — **how do we skip redundant multiplications?**

**Example 1:**
```
Input:  x = 2.00000, n = 10
Output: 1024.00000
```

**Example 2:**
```
Input:  x = 2.10000, n = 3
Output: 9.26100
```

**Example 3:**
```
Input:  x = 2.00000, n = -2
Output: 0.25000
Explanation: 2⁻² = 1/2² = 1/4 = 0.25
```

**Constraints:**
- $-100.0 < x < 100.0$
- $-2^{31} \le n \le 2^{31} - 1$
- $n$ is an integer
- Either $x \neq 0$ or $n > 0$

## Approach 1 — Brute Force (Linear Multiplication)

**First instinct:** Just multiply `x` by itself `n` times. If `n` is negative, flip `x` to `1/x` and work with `|n|`.

Let's trace through `x = 2, n = 5`:
```
result = 1.0
i=0: result = 1.0 * 2 = 2.0
i=1: result = 2.0 * 2 = 4.0
i=2: result = 4.0 * 2 = 8.0
i=3: result = 8.0 * 2 = 16.0
i=4: result = 16.0 * 2 = 32.0 ✓
```

Simple enough — but what if `n = 2,000,000,000`? That's 2 billion multiplications. TLE.

```cpp
class Solution {
public:
    double myPow(double x, int n) {
        long long N = n;            // long long to safely negate INT_MIN
        if (N < 0) { x = 1 / x; N = -N; }

        double result = 1.0;
        for (long long i = 0; i < N; i++)
            result *= x;
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(1)$ |

> **Verdict:** Correct but way too slow for large `n`. We need to cut down the number of multiplications.

## Approach 2 — Binary Exponentiation (Recursive)

**The key insight:** We're doing redundant work. $x^{10}$ is just $(x^5)^2$, and $x^5$ is $x \cdot (x^2)^2$. Each step halves the problem — so we only need $\log n$ steps instead of $n$.

The recurrence:

$$x^n = \begin{cases} 1 & \text{if } n = 0 \\\ (x^{n/2})^2 & \text{if } n \text{ is even} \\\ x \cdot (x^{n/2})^2 & \text{if } n \text{ is odd} \end{cases}$$

Let's trace `x = 2, n = 10` step by step:
```
pow(2, 10)
 └─ half = pow(2, 5)
     └─ half = pow(2, 2)
         └─ half = pow(2, 1)
             └─ half = pow(2, 0) → 1.0
             n=1 is odd → 1.0 * 1.0 * 2 = 2.0
         n=2 is even → 2.0 * 2.0 = 4.0
     n=5 is odd → 4.0 * 4.0 * 2 = 32.0
 n=10 is even → 32.0 * 32.0 = 1024.0 ✓
```

Only **4 recursive calls** vs 10 multiplications in brute force. For `n = 2 billion`, that's just ~31 calls.

```cpp
class Solution {
public:
    double myPow(double x, int n) {
        long long N = n;
        if (N < 0) { x = 1 / x; N = -N; }
        return fastPow(x, N);
    }

private:
    double fastPow(double x, long long n) {
        if (n == 0) return 1.0;
        double half = fastPow(x, n / 2);
        return (n % 2 == 0) ? half * half : half * half * x;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(\log n)$ | $O(\log n)$ — recursion stack |

> **Much better!** But we're using $O(\log n)$ stack space. Can we flatten this into a loop?

## Approach 3 — Binary Exponentiation (Iterative) ✅

**Same core idea, zero recursion.** Think of `n` in binary — each `1` bit corresponds to a power of `x` that contributes to the result.

Take `n = 13 = 1101₂`:  
$$x^{13} = x^8 \cdot x^4 \cdot x^1$$

We maintain a running `x` that doubles its exponent each step (by squaring). Whenever the current bit of `n` is `1`, we multiply that power into `result`.

Trace with `x = 2, n = 13`:
```
N=13 (1101₂), result=1.0, x=2

Bit 0 (1): N is odd  → result = 1.0 * 2 = 2.0     | x = 2² = 4    | N = 6
Bit 1 (0): N is even → result stays 2.0             | x = 4² = 16   | N = 3
Bit 2 (1): N is odd  → result = 2.0 * 16 = 32.0    | x = 16² = 256 | N = 1
Bit 3 (1): N is odd  → result = 32.0 * 256 = 8192.0 | N = 0 → done

result = 8192.0 = 2¹³ ✓
```

```cpp
class Solution {
public:
    double myPow(double x, int n) {
        long long N = n;
        if (N < 0) { x = 1 / x; N = -N; }

        double result = 1.0;
        while (N > 0) {
            if (N & 1) result *= x;   // current bit is set → pick up this power
            x *= x;                   // square x for the next bit position
            N >>= 1;                  // move to next bit
        }
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(\log n)$ | $O(1)$ |

> **This is the one.** Same $O(\log n)$ speed, constant space, clean loop.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| `n = 0` | Any $x^0 = 1$ | Loop doesn't execute, returns `1.0` |
| `n = INT_MIN` | `-INT_MIN` overflows `int` | Use `long long N = n` before negating |
| `x = 0, n < 0` | $0^{-k}$ = division by zero | Problem guarantees this won't happen |
| `x = 1` or `x = -1` | Result is trivially `1` or `±1` | Works naturally, no special case needed |
| `n` is negative | $x^{-n} = (1/x)^n$ | Flip `x` to `1/x` and negate `N` upfront |

---

## Pattern Takeaway

**Binary exponentiation** (exponentiation by squaring) is a foundational technique. The core trick: **halve the problem each step by squaring.** You'll see this same idea in:

- **Modular exponentiation** — computing $a^b \mod m$ in crypto/competitive programming
- **Matrix exponentiation** — computing Fibonacci in $O(\log n)$
- **Fast power in general** — anywhere "raise to a huge power" appears

Whenever the exponent is massive and the operation is associative — reach for this.
